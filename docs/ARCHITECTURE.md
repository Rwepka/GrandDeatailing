# Архитектура и стандарты GRAND DETAILING

Документ описывает устройство сайта, правила разработки и принятые стандарты. Его нужно читать перед любыми правками, чтобы не ломать существующую архитектуру. При изменении архитектуры документ обновляется в том же коммите.

## 1. Стек и среда

| Параметр | Значение |
|---|---|
| Язык | PHP 8.x, `declare(strict_types=1)` в прикладном коде |
| БД | MySQL 8 / MariaDB 10.5+, PDO, `utf8mb4` |
| Фронтенд | Vanilla HTML/CSS/JS, без сборщика и npm |
| Веб-сервер | Apache + `mod_rewrite` на проде; `php -S` локально |
| Домен | https://grand-detailing.ru, REG.RU shared hosting |
| Локально | `http://localhost:8000`, порт MySQL 3306 |

Локальный PHP: `C:\Users\Rwepka\dev\php84\php.exe` (8.4.28 NTS, расширения `pdo_mysql`, `mbstring`, `gd`, `intl`, `openssl`, `curl`, `fileinfo`). Каталог добавлен в пользовательский `PATH`; для текущих оболочек также создан `php.cmd`-лаунчер.

### Локальная производительность

На Windows PHP + MariaDB подключение к `localhost` может сначала пытаться открыть IPv6 (`::1`) и ждать ~2 секунды. Если БД слушает только `127.0.0.1`, каждый HTML-запрос получает TTFB ≈ 2 с.

**Стандарт для локальной среды:** в `config/config.php` указывать `db.host = '127.0.0.1'`. На Linux-хостинге допустим `localhost` (unix socket). Статика отдаётся быстро, проблема проявляется только на страницах с БД.

  bootstrap.php         # timezone, сессия, автозагрузка, helpers

  Core/Router.php       # GET/POST, {id}/{slug}
  Core/Database.php     # PDO singleton
  Core/View.php         # layout + view, renderAdmin()
  Controller/           # публичные, Auth, Cabinet, Admin*

## 3. Жизненный цикл запроса

1. Apache/`php -S` направляет всё, кроме существующих файлов, в `public/index.php`.
2. `BASE_PATH` = корень проекта; подключается `src/bootstrap.php`.
3. `bootstrap.php`: `date_default_timezone_set('Europe/Moscow')`, helpers, настройки ошибок, сессия в `storage/sessions`, автозагрузка `App\*`, auto-login по remember-cookie.
4. `public/index.php` создаёт `Router`, регистрирует маршруты и вызывает `dispatch()`.
5. `Router` находит обработчик `[Controller::class, 'method']`, создаёт контроллер и вызывает метод с параметрами URL.
6. Контроллер проверяет доступ (`requireAdmin`, `requireStaff`, `requireAuth`), CSRF, валидирует POST, вызывает модель, затем `View::render()` / `View::renderAdmin()` или `redirect()`.
7. `View` подключает `layout/header.php` + view + `layout/footer.php`; данные передаются через `extract($data, EXTR_SKIP)`.
8. Модели работают через `Database::connection()` (PDO singleton, prepared statements, `ATTR_EMULATE_PREPARES => false`).

### Маршруты

- Публичные: `/`, `/services`, `/services/{slug}`, `/booking`, `/contacts`, `/reviews`, `/news`, `/sitemap.xml`, `/robots.txt`.
- Авторизация: `/login`, `/register`, `/logout`.
- Кабинет: `/cabinet/*` (только авторизованные).
- Админка: `/admin/*` (администратор или мастер — через guard).
- Новые маршруты добавляются только в `public/index.php`; контроллер не должен сам разбирать `REQUEST_URI`.

### Важные инварианты

- Веб-корень — только `public/`. Конфиг, PHP-код, шаблоны и `storage/` лежат выше и закрыты `.htaccess`.
- `config/config.php` не коммитится; в репозитории только `config.example.php`.
- Все SQL-запросы — через PDO prepared statements.
- Любой вывод в HTML — через `e()`.
- POST-формы — с `csrf_field()` и `csrf_verify()`.
- Редиректы после POST — `redirect()` (PRG).
- Для новых таблиц/полей — миграция в `database/migrations/`, обновление `schema.sql` и модели.
- Никаких бизнес-данных (услуги, FAQ, цены, тексты карточек) в контроллерах/шаблонах: источник — БД, редактирование — админка.

## 4. База данных

Ключевые таблицы:

| Таблица | Назначение |
|---|---|
| `roles` | client / admin / master |
| `users` | клиенты, админы, мастера; `role_id`, `must_change_password`, `verified_at` |
| `categories` | категории услуг |
| `services` | услуги: title, slug, short_description, description, includes, process, price_from, duration_min, image, is_active |
| `service_prices` | цена услуги по типу кузова (`body_type`), уникальность service_id+body_type |
| `bookings`, `booking_items` | заявки и позиции с зафиксированной ценой |
| `reviews`, `posts`, `messages`, `works` | контент сайта |
| `faqs` | вопросы/ответы для блока на главной (sort_order, is_active) |
| `settings` | key/value: адрес, телефон, часы, карта, коды верификации |
| `audit_log` | действия в админке |
| `rate_limits`, `login_attempts`, `remember_tokens` | безопасность |

### Правила данных

- `services.price_from` — вычисляемый минимум из `service_prices`, если цены по кузовам заданы; иначе NULL/ручная цена.
- `services.short_description` — текст для карточки (до 255 символов).
- `services.description` — полный текст для страницы услуги.
- `services.includes`, `services.process` — многострочный текст, по одному пункту на строку; выводятся списками.
- `faqs` — единственный источник блока «Частые вопросы» на главной; других FAQ-блоков на сайте нет.
- Категории и услуги создаются/редактируются только в админке; в коде допустимы только демо-данные `seed.sql`.

## 5. Стандарты админки

Каждый CRUD-раздел:

1. `AdminXController` с `requireAdmin()` (или `requireStaff()` для заявок).
2. Экшены `index`, `create`, `store`, `edit`, `update`, `toggle`, `delete` по необходимости.
3. CSRF во всех POST; при ошибке — повторный рендер с `errors`, `old`, сохранёнными значениями.
4. `AuditLog::record()` на создание/изменение/удаление.
5. `setFlash()` + `redirect()` после успеха.
6. View в `views/admin/`: список (`admin-table`) и форма (`card`, `field-group`, `fieldset`, кнопки `btn-accent`/`btn-outline`).
7. Ссылка в `views/admin/layout/header.php` с SVG-иконкой и `nav_attrs()`.

### Визуальные стандарты админки

- Формы-карточки: тёмная подложка `#1f2330`, рамка `#3a4150`, ширина по полям (не на всю страницу), светлые подписи, белые инпуты.
- Элементы таблиц: кнопки и селекты высотой 36 px, радиус 8 px, шрифт 13–14 px; действия переносятся на новую строку, а не обрезаются.
- Бейджи статусов — 26 px, выровнены по центру строки.
- Тексты отзывов и служебные подписи — светлые (`#f1f5f9` / `#94a3b8`), тёмный текст на тёмном фоне запрещён.
- Модальные окна — тот же тёмный фон `#1f2330` с рамкой.

### Форма услуги (стандарт)

Поля: название, slug, категория, краткое описание, полное описание, «Что входит» (по строке), «Как проходит работа» (по строке), базовая «Цена от» (если цены по кузовам не заданы), цены по классам кузова, длительность. Slug проверяется на уникальность до записи (`Service::slugExists`, с исключением текущей услуги при редактировании). Все текстовые поля сохраняются в `services`; карточки и страница услуги читают только БД. Если заданы цены по кузовам, `price_from` вычисляется как минимум; иначе берётся базовая цена. Отдельных статических страниц услуг (например, `/tonirovka`) быть не должно — любая услуга создаётся в админке.

### FAQ (стандарт)

Раздел «Вопросы» в админке (`/admin/faqs`) — единственный способ наполнения блока «Частые вопросы». Поля: вопрос, ответ, порядок, видимость. Блок и `FAQPage` выводятся только на главной и только для активных записей. Модель — `App\Model\Faq`, контроллер — `AdminFaqController`, шаблоны — `views/admin/faqs.php` и `faq_form.php`.

## 6. Публичные стандарты

### Навигация

- Пункты: Главная, Услуги, Новости, Отзывы, Контакты (для мастера — только Контакты).
- В шапке **нет** кнопок «Выйти», «Записаться», «Тонировка».
- CTA записи живёт в контенте страниц (hero, карточки, страница услуги, футер).
- Логотип на всех страницах — текстовый `GD` цвета `#7e8891`.
- Мобильное меню — гамбургер; на планшете до 1200 px — тот же режим.

### Региональные упоминания

- Город/регион допустим в `<title>`, meta description, JSON-LD, адресе и блоке под калькулятором на главной.
- В остальных видимых заголовках, лидах и текстах города нет: H1 услуг/записи/отзывов/новостей/контактов — без «в Туапсе».
- Контактный адрес — фактическая информация, его не удаляем.

### Дизайн-система

| Токен | Значение |
|---|---|
| Фон | `#252633` / muted `#1E1F2B` |
| Сатин (карточки, кнопки) | `#7e8891` |
| Светлая обводка | `rgba(255,255,255,.55)` |
| Акцент действий | `#1D4ED8` |
| Успех (пройденные шаги) | `#DCFCE7`, текст `#14532D` |
| Чекбоксы | заливка `#1F2330`, белая внутренняя обводка 3 px, белая галочка, масштаб 0.8 |
| Шрифт | Inter (self-hosted, cyrillic + latin) |
| Радиус | 12 px, кнопки min-height 44 px |

Правила:

- Никаких металлических текстур, шума, градиентных бликов. Только сплошной `#7e8891`.
- Один H1 на страницу; далее H2/H3 по смыслу.
- Цены — `price()` / `.price` / `.price-xl`, tabular-nums, «от N ₽».
- Кнопки не примыкают к тексту: отступы через `.form-actions`, `.step-actions`, `gap`.
- Радио и чекбоксы визуально скрыты; используются сегментированные контролы и карточки с кастомной галочкой. Переходы состояний — 150–250 ms, с `prefers-reduced-motion`.
- Выбранная карточка услуги (калькулятор, квиз, админка) получает светлую заливку `#F1F5F9`, тёмную галочку `#1F2330` (масштаб 0.8) и такой же контур — поведение единое.
- Цены для JS-калькулятора передаются в `data-price` / `data-prices` на обёртке карточки (`.calculator-service` / `.service-card`); скрипт допускает fallback на input.
- Сетки карточек и калькуляторов — равная высота (`grid-auto-rows: 1fr`).

### SEO

- Уникальные title/description на страницах; город — в metadata, не в каждом H1.
- Один H1; осмысленные H2.
- JSON-LD: `AutoWash` (бизнес), `Service` (услуга), `BreadcrumbList`, `FAQPage` только для FAQ на главной.
- Canonical, OG/Twitter, `robots` noindex для `/admin`, `/cabinet`, `/login`, `/register`, служебных страниц.
- `sitemap.xml` и `robots.txt` динамические, домен из `config('app.url')`.
- FAQ для schema — только из БД (`faqs`), не хардкодить.
- Верификация Search Console/Вебмастера — поля в настройках админки; IndexNow — скрипт `scripts/indexnow.php`.

## 7. Стандарты кода и ревью

- Не менять глобальные константы, timezone, схему БД без записи в этом документе и миграции.
- Не добавлять статические страницы-дубли сервисов: любая услуга — запись в `services`.
- Не хардкодить телефоны, адреса, часы, тексты услуг и FAQ в шаблонах; только `setting()` / БД.
- Новые CSS-классы — в `public/assets/css/style.css` (публичные) или `admin.css` (админка); не дублировать одинаковые компоненты.
- JS — в `public/assets/js/main.js` / `admin.js`, без внешних библиотек.
- После изменений: `php -l`, HTTP-смоук, проверка мобильной вёрстки, JSON-LD, ссылок.
- Любое отклонение от требований фиксируется в отчёте; не делать «улучшений» без запроса.

## 9. Известные ограничения

- Статика кэшируется по `?v=mtime` с точностью до секунды: при быстрых правках локально браузер может держать старую CSS-версию; для проверки — hard reload.
- `php -S` однопоточный; при большом числе параллельных запросов возможна очередь. Для локальной разработки допустимо.
- На проде нужны `mod_rewrite`, `mod_headers`, права на `storage/`, cron очистки.
- Широкие SEO-запросы («детейлинг», «полировка») не гарантируются; приоритет — локальная выдача и карточки услуг.
