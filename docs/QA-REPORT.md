# QA-отчёт: правки GRAND DETAILING

Дата: 24.11.2026. Среда: локальный PHP 8.4.28 + MariaDB 11.4.14, `http://localhost:8000`.

## 1. Производительность

Причина медленной работы найдена: PHP на Windows подключался к `localhost`, сначала шёл в IPv6 `::1`, ждал ~2 секунды и только потом использовал `127.0.0.1`.

| Запрос | До | После (`db.host = 127.0.0.1`) |
|---|---|---|
| `/` TTFB | ~2,05 с | ~0,02 с |
| `/services` TTFB | ~2,05 с | ~0,005 с |
| `/booking` TTFB | ~2,04 с | ~0,005 с |
| CSS/JS/изображения | ~0,001 с | ~0,001 с |
| Полная загрузка главной в браузере (локально, кэш) | — | TTFB 6 мс, DOMContentLoaded 17 мс, load 97 мс |

На проде Linux shared hosting использует `localhost`/unix socket — там задержки нет. Для локальной Windows в `config/config.php` теперь `127.0.0.1`.

## 2. Архитектура и БД

Добавлены миграции:

- `007_service_content.sql` — поля `services.short_description`, `description`, `includes`, `process`.
- `008_faqs.sql` — таблица `faqs` (question, answer, sort_order, is_active).

Проверено:

- админ создаёт услугу через `/admin/services/create`, все текстовые поля и цены сохраняются в БД;
- страница `/services/{slug}` и карточки на `/` и `/services` читают данные из БД;
- админ создаёт/удаляет FAQ через `/admin/faqs`; блок появляется только на главной;
- статическая страница `/tonirovka` удалена, услуга при необходимости создаётся администратором.

## 4. Найденные и исправленные баги

| Баг | Проявление | Исправление | Проверка |
|---|---|---|---|
| Дубликат slug услуги | Создание/редактирование услуги с существующим slug давало необработанный `PDOException` и 500 | Добавлена проверка `Service::slugExists()` с исключением текущей услуги; ошибка выводится в форме | Повторный POST с `slug=moyka` — 200 и сообщение «Услуга с таким slug уже существует»; сохранение той же услуги без смены slug — 302 |
| Потеря `price_from` при редактировании | Если у услуги не было цен по кузовам, сохранение формы обнуляло «Цену от» | Добавлено отдельное поле «Цена от, ₽»; при отсутствии цен по кузовам сохраняется базовая цена | Создание услуги с `price_from=5000` — сохранилось; добавление цен по кузовам — `price_from` стал минимумом (1000) |
| Калькулятор на главной показывал 0 | Цены лежали на input, а JS искал их на карточке | Атрибуты перенесены на `.calculator-service`, JS поддерживает оба варианта | «Мойка» + «Седан» → 1 000 ₽ |
| Пустой блок отзывов размечен `aggregateRating` с 0 | При отсутствии опубликованных отзывов выводилась rating 0 / reviewCount 0 | `aggregateRating` выводится только при `reviewCount > 0` | Временно сняты публикации — страница 200, `aggregateRating` отсутствует; публикации восстановлены |
| Пустой FAQ оставлял секцию/схему | При отключении всех вопросов на главной мог оставаться `FAQPage` | Секция и schema выводятся только при наличии активных `faqs` | Все FAQ временно скрыты — секции и `FAQPage` нет; восстановлены |

## 8. SEO

- FAQ-блок и `FAQPage` — только на главной, данные из `faqs`.
- Страницы услуг и `Service` JSON-LD — из `services`.
- Город оставлен в title/description, JSON-LD, адресе и блоке под калькулятором.
- В H1 и остальных видимых текстах города нет (кроме контактного адреса).
- `sitemap.xml` формируется из БД, статической `/tonirovka` больше нет.

## 9. Наблюдения

- После входа администратор попадает в `/admin`, мастер — в `/admin/bookings`, клиент — в `/cabinet`.
- В локальной БД остаётся тестовая заявка № 7 («Иван», «Седан») — не удалял, так как она могла быть создана вручную.

## 10. Остаточные внешние действия

1. Применить миграции 007/008 на проде.
2. Заполнить описания услуг и FAQ в админке.
3. Выложить файлы и проверить `config('app.url')`, `debug = false`.
4. Заполнить коды Search Console/Яндекс.Вебмастера, отправить sitemap, запустить IndexNow.
5. Синхронизировать телефон и часы работы с Яндекс.Картами/2ГИС/Zoon.
